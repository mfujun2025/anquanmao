### 0.2 统计口径

- **字数**：脚本按 `[\u4e00-\u9fff]` 统计纯汉字数（不含标点、数字、字母、空白）；另给「正文全字符数（去空白）」作参照。交付稿 frontmatter、文末 `Meta Title:` 区块不计入正文。因此本报告字数与 `delivery-report` 的「中文字数」略有差异，属口径不同，非数据冲突——**所有篇目均远超 2,500 字硬规格**。
- **句长**：按 `。！？` 与换行切分，统计每句汉字数。
- **段落**：按「非空、非标题、非表格、非引用、非列表」筛出散文段，统计段长与「超过 4 句」的段数。
- **导语**：H1 之后、第一个 H2 之前的首个自然段（不含「关键要点」引用块）。
- **主词密度**：本报告只做定性判断（主词是否自然分布在 H1 / 导语 / H2 / 表格 / FAQ / 结论），**精确密度复核属 SEO 联审职责**，不与 `seo-optimizer` 的数值口径比较，也不对其结论置评。

## 2. AI 痕迹检测

### 2.1 硬套话：零命中（如实说明）

对 5 篇全文检索 `随着 / 在当今 / 当今社会 / 众所周知 / 综上所述 / 值得注意的是 / 毋庸置疑 / 不难看出 / 总而言之 / 显而易见 / 一言以蔽之 / 让我们 / 不言而喻 / 不可忽视 / 至关重要 / 日益 / 赋能 / 抓手` 等典型 AI 套话与陈词——**0 命中**。5 篇导语全部用真实事件或反直觉提问开场，符合 Brief §10 第 6 条。这一项撰稿人守得很干净，必须记功，不能为凑「痕迹条数」硬找。

同时复核了「空泛句 / 无来源绝对化数据 / 编造品牌排名 / 无上下文列表堆砌 / 薄弱结论」五类红旗：**均未发现**。每个主要论点都有数字、政策文号、标准条款或可复制清单支撑；结论都落在可执行的下一步，没有「重要性不言而喻」式收尾。

### 4.4 关于「等效 Flesch」的说明与中文适配局限

- Flesch Reading Ease / Flesch–Kincaid Grade 依赖**英文音节数与按空格分词的词数**，中文没有空格分词、没有可比的音节计数，直接套用公式会严重失真；常见「中文 Flesch 换算」多是按句长与字频做经验回归，**只能作趋势参考，不能当作绝对可读性结论**。
- 若以「平均句长 + 平均段长 + 术语密度 + 每百字标点数」做等效类比，这批稿件大致落在 **Flesch 55–65（Fairly Difficult / Standard）** 区间，对应中文「中等偏专业、需高中以上或行业经验」——与 Brief §2 的采购专员/安全员/个体用户画像基本匹配，不算劝退。
- 因此本报告**以中文四项实测（句长、段长、术语白话率、表格节奏）为主要判据**，等效 Flesch 仅作辅助说明，不建议把该数值写进发布验收口径。

## 6. 篇 2「唯一」一句：不损失语义、不触发绝对化用语的替代表述

### 6.1 原文（篇 2 · 第 26 行）

> 「全文可在国家标准全文公开系统查阅，这也是核对任何条款时的**唯一权威底本**——网上二手整理、厂商软文里的数字，最终都要回到这里复核。」

### 6.2 问题

- 「唯一」属《广告法》第九条语境下的绝对化用语（「唯一 / 第一 / 最 / 国家级 / 最佳」同类），`audit.py` 违禁词扫描已命中（`delivery-report` §3 备注亦记录）；
- 「权威底本」叠加强化了排他性，对一个中立合规站而言不必要；
- 原意其实很朴素：**核对条款以国标全文现行有效版本为准，二手整理只能当线索**。这个语义完全可以用非绝对化表达保住，且更贴合 Brief §10 第 3 条「以国标全文公开系统现行版本为准」的既有口径。

### 6.3 替代表述（推荐第 1 条）

1. **【推荐】**「全文可在国家标准全文公开系统查阅，**核对任何条款都应以这份现行有效版本为准**——网上二手整理、厂商软文里的数字，最终都要回到原文复核。」
   → 只替换「唯一权威底本」为「以这份现行有效版本为准」，语义不损、语气更严谨，且顺带呼应「修订动向需留余地」的全站纪律；破折号可保留（此处确为补充说明）。
2. 「核对任何条款，建议都回到国家标准全文公开系统收录的现行版本；**二手整理与厂商软文可作检索线索，不宜直接当依据**。」
   → 把「权威」拆成「线索 / 依据」的功能区分，最中立，适合放进编标/验收语境。
3. 「全文可在国家标准全文公开系统查阅。遇到条款口径不一致时，**以该系统登记的现行有效版本为准**，二手资料仅作参考。」
   → 加了触发条件「口径不一致时」，最保守，适合法务复审口径。

### 6.4 ⚠️ 一个必须回传的联动风险

- 发布页 `blog/gb-2811-2019-safety-helmet-standard.html` 第 38 行**已经**改为「核对任何条款都应以这份原文为准——网上二手整理…回到这里复核」，即整合阶段已规避；
- 但**源稿 `articles/gb-2811-2019-safety-helmet-standard.md` 第 26 行仍是「唯一权威底本」**，两者不一致；
- `delivery-report` §2 说明 `tools/build_articles.py` 会**把 `articles/*.md` 重新构建为 `blog/*.html`**——若只改了 HTML 未回写 Markdown，**下次例行构建会把「唯一」重新带回发布页**，导致违禁词扫描再次命中。
- **建议**：按 6.3 第 1 条回写原稿第 26 行，使源稿与发布页一致，并在 `audit.py` 复验前重跑一次构建。此项属发布流程联动，请主理人转交撰稿/发布环节执行（本报告不修改任何文件）。
