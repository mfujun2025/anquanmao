## 2. 关键词分布热图

### 2.1 口径说明（重要，影响验收结论）

老孟规格写「主词密度 1%–2%（按中文字符计，2500 字 ≈ 出现 25–50 次）」，但 Brief §5 这句换算存在内在矛盾：25 次 ÷ 2500 字 = 1%，这是把**出现次数**当分子、**字数**当分母（英文 SEO "keyword count / total words" 的直译）。中文长尾主词是 5–7 字的词组，若按此字面口径，5300 字的文章要塞进 53–106 次「安全帽怎么选」才算 1%，属于明显堆砌，与 Brief「禁止堆砌」「自然流畅」直接冲突。

因此本报告给出**双口径实测**，并建议以「字符加权密度」为验收口径：

- **字符加权密度**（推荐）= 主词字符数 × 出现次数 ÷ 正文汉字数。这是中文 SEO 衡量「主词字面覆盖」的合理口径。
- **频次密度**（字面口径）= 出现次数 ÷ 正文汉字数。供对照，不建议据此补词。

## 4. 结构化数据建议

### 4.1 现状盘点（实测）

5 篇发布页的 JSON-LD 均为**两段独立 `<script type="application/ld+json">`**：

- `Article`：`headline`（= Meta Title，59 字符，符合 ≤110 建议值）、`description`、`inLanguage: zh-CN`、`datePublished` / `dateModified`（均 2026-11-10）、`author` / `publisher`（Organization「安全帽.cn」）、`mainEntityOfPage`（WebPage，指向自身 canonical）。
- `BreadcrumbList`：3 级（首页 → 安全帽知识 → 本篇分类），`ListItem` 结构完整。
- `audit.py` 已逐页 `json.loads()` 校验通过，无解析错误。

**结论：现有 Article + BreadcrumbList 对「让搜索引擎正确识别文章与站内外位置」已经够用，且字段质量高于同类站点平均水平。** 缺的是**内容语义层**的标注，不是修复性问题。

### 4.2 是否补 FAQPage / HowTo / ItemList（结论先行）

| 类型 | 建议 | 理由（含收益的诚实评估） |
|---|---|---|
| **FAQPage** | **建议补，中优先级** | 5 篇均有 5–6 组「问：…／答：…」可见 FAQ，是现成的标注素材，零改写成本。但须诚实说明：**Google 自 2023-08 起已将 FAQ 富摘要限制为权威政府/健康类站点，一般商业站基本不再展示 FAQ rich result**。补它的真实收益是语义消歧、AI 摘要/答案引擎引用（本站已有 `llms.txt`）、以及百度等仍读取 FAQ 结构的引擎，**不应承诺 Google 富摘要**。 |
| **HowTo** | **不建议补（低收益）** | 篇 1「五步决策」、篇 5「正确佩戴五步法」确实是步骤型内容，但 **Google 已于 2023 年全面弃用 HowTo 富摘要（搜索结果移除）**。补了只增加维护成本与「结构化数据与可见内容一致性」的合规负担，收益接近 0。若要抢步骤型摘要，靠 `<ol>` + 40–60 字直答（§5）比 HowTo 标记更有效。 |
| **ItemList** | **可选，最低优先级** | 篇 2「6 项永久标识」有序清单、篇 3「四材质对照表」、篇 4「八类工况表」可标为 ItemList，但对中文 SERP 无稳定富摘要收益。建议与 FAQPage 一起做，不单独排期。 |
| **Article 字段增强** | **建议补，最高优先级（成本最低）** | 现有 Article 缺 `image`、`wordCount`、`articleSection`、`about` / `mentions`、`citation`、`isAccessibleForFree`。其中 `citation` 可直接挂 Brief §7.4 的权威外链 URL，`about` 可指向 GB 2811-2019 实体，对「合规纠偏型内容」的实体识别最有帮助。 |

### 4.3 具体补法（给 build 阶段的落点，本报告不改脚本）

**（A）Article 增补字段** —— 在现有 Article 对象内追加，不动既有字段：

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "...（沿用 §9 实测版 Meta Title，勿改）",
  "description": "...（沿用 §9 实测版 Meta Description，勿改）",
  "inLanguage": "zh-CN",
  "datePublished": "2026-11-10",
  "dateModified": "2026-11-10",
  "author": { "@type": "Organization", "name": "安全帽.cn" },
  "publisher": { "@type": "Organization", "name": "安全帽.cn" },
  "mainEntityOfPage": { "@type": "WebPage", "@id": "https://xn--15qt0wm7b.cn/blog/<slug>.html" },
  "image": "https://xn--15qt0wm7b.cn/assets/img/<slug>-cover.svg",
  "articleSection": "采购决策指南",
  "wordCount": 5331,
  "isAccessibleForFree": true,
  "about": { "@type": "Thing", "name": "GB 2811-2019 头部防护 安全帽" },
  "citation": [
    "https://openstd.samr.gov.cn/bzgk/gb/newGbInfo?hcno=ACF9D1C05F42220BA2B24036E5904505",
    "https://www.gov.cn/zhengce/zhengceku/202406/content_6959300.htm"
  ]
}
```

> 注：`image` 需指向真实存在的 `assets/img/` 文件（Brief §7.3 建议的示意图），**不可填不存在路径**，否则 audit.py 的链接检查与 Search Console 都会报错；若无图，宁可省略该字段。`wordCount` 用本报告 §2.4 的实测汉字数。`citation` 每篇取该篇实际引用的 2–3 个权威域，与正文可见链接一一对应。

**（B）FAQPage 增补** —— 作为第三个独立 JSON-LD 块，或在现有数组内追加。**硬约束：`acceptedAnswer.text` 必须与页面可见 FAQ 答案逐字一致**（Google 结构化数据政策要求答案在页面可见），不可另写摘要版：

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "安全帽怎么选才不算违规？",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "认准三样并留下记录即可——GB 2811-2019 标准编号、工业产品生产许可证编号与标识、覆盖所采购性能项的检测报告，再核对帽壳内侧 6 项永久标识。……"
      }
    }
  ]
}
```

> 每篇 5–6 个 `Question`，逐条抄该篇 FAQ 的「问：」与「答：」全文。建议由 `build.py` 从 Markdown 的 FAQ 段自动解析生成，避免手工维护导致 JSON-LD 与正文脱节。生成后必须重跑 `audit.py`（它会 `json.loads()` 校验每个 LD 块）。

**（C）不建议做的事**：不要为了「看起来更完整」而同时塞 `HowTo`、`QAPage`、`ItemList`、`Product`、`AggregateRating`。本站是资讯/决策型内容，`Product`/`AggregateRating` 应留给 `products/` 商品页；堆砌无关类型会稀释实体识别，且触发结构化数据垃圾风险。

## 5. 精选摘要（Featured Snippet）捕获建议

**通用写法**：问句式 H2 → 紧跟一个 **40–60 字加粗独立段落**（`<p><strong>…</strong></p>`，不裹在长段里）→ 紧跟 `<ol>` / `<table>`。Google / 百度抽取的是「H2 之后第一个完整文本块 + 紧邻的结构化元素」，直答块前后不要插配图、引用或过渡句。以下逐篇给出**精确落点**与**可直接使用的直答文案**（字数已实测）。

### 篇 1｜安全帽怎么选（列表型 + 表格型）
- **落点**：现有一句直答藏在导语里（「安全帽怎么选？先给一句能直接抄进采购单的答案：按……五步走」），导语不是最佳抽取位。建议在 H2「一、先搞清楚」**之前**新增一个 H2「安全帽怎么选：五步直答」，其下放直答段 + 五步有序列表。
- **直答文案（60 字）**：
  > **安全帽怎么选？按查资质、定材质、对场景、看结构、做验收五步走，每步都留下可复核的书面依据，不推品牌、只认标准与检测报告。**
- **配套结构**：紧跟 `<ol>` 列出五步，每步一句 12–18 字，并内链对应支撑篇（复用 §9 锚文本表）。现有「到货抽样验收核对表」与「关键要点」blockquote 可保留，但**不要插在直答段与列表之间**。

### 篇 2｜安全帽国家标准（定义型 + 列表型，机会最强之一）
- **落点**：H2「一、现行有效的是哪一版：安全帽国家标准身份卡」下方已有一句加粗定义，但实测约 80 字，超出 40–60 字最佳区间，且与后文连成一段。建议**压缩并独立成段**，置于该 H2 正下方第一行。
- **直答文案（53 字）**：
  > **现行安全帽国家标准是 GB 2811-2019《头部防护 安全帽》，2020 年 7 月 1 日实施，代替 2007 版。**
- **第二个摘要位**：H2「四、帽壳内侧的 6 项永久标识」下已有 1–6 有序清单，**保持原样即可**，这是标准的列表型摘要候选；只需把该 H2 改成问句「安全帽国家标准要求哪 6 项永久标识？」以匹配查询句式（同时顺带解决本篇含主词 H2 偏少的问题）。

### 篇 3｜安全帽材质（表格型）
- **落点**：H2「三、【核心对照表】四材质 × 8 维度」的表格**上方**新增一个 40–60 字定义型直答段，并把表格标题「安全帽材质·四材料性能成本对照表」提升为含主词的 `<h3>`，表格首列表头由「维度」改为「安全帽材质对比维度」——**表头含主词是表格型摘要被抽取的关键**。

### 篇 4｜安全帽选型（表格型）
- **落点**：H2「二、【核心对照表】八类工况安全帽选型速查」下方，表格之前补直答段。该表已是 Brief 指定的核心资产、标题已含主词，可保持不动。

### 篇 5｜安全帽使用期限（数字直答型 + 步骤型，**全站最强，几乎现成**）

- **直答文案（59 字，沿用原文即可）**：
  > **安全帽使用期限按材质分：塑料类不超过 2.5 年、玻璃钢类不超过 3.5 年，自制造完成之日起算；帽壳内侧须标注强制报废期限。**
- **第二个摘要位**：H2「四、正确佩戴五步法：查、调、留、系、护」下的 `<ol>` 是标准步骤型摘要候选，保持原样；只需在该 H2 下补一句 30 字以内的引导句，不要插入长段落。

**优先级**：篇 5 > 篇 2 > 篇 1 > 篇 4 > 篇 3。篇 5 与篇 2 建议随发布顺序（Brief §4.4：篇 1 → 篇 5 → 篇 2）优先落地，这两篇的问句最明确、竞品多为碎片化消费提示，抢位成本最低。
